# `/v1` Route Inventory (Contracts-First, Phase 1)

This is the `/v1` endpoint inventory for the Clubroom backend. It is intentionally broader than any one route module and should be kept aligned with implemented runtime behavior.

Status legend:

- `implemented`: route exists in `apps/api` and now uses a runtime-backed repository/persistence path
- `planned`: contract + authz + data model defined, implementation pending
- `deferred`: intentionally after phase 1 or later sprint

## Inventory Rules

- Every row must eventually include:
  - shared contract name(s)
  - authz rule summary (role + grants + safety gates)
  - idempotency requirement (for writes)
  - versioning/conflict requirement (for mutable resources)
  - UI route/service anchors
- `npm run api:openapi` regenerates the checked-in OpenAPI document from `implemented` rows in this inventory.
- Route-specific OpenAPI overrides live in `scripts/generate-openapi-from-route-inventory.js` when a high-value route needs explicit tags, query parameters, or request/response schemas beyond the inventory row summary.
- OpenAPI/Swagger routes are enabled by default outside production. Production must opt in with `API_OPENAPI_ENABLED=1`.
- HTTP `DELETE` remains valid for resource removal endpoints, but human-facing product copy and audit-log rendering must describe the real effect: `archive`, `remove`, `dismiss`, `revoke`, `cancel`, or `void`. For example, render `athlete.remove` as “Athlete removed” rather than showing raw action IDs to users.
